Deploy Storyboard Studio ke Dokploy

Panduan langkah demi langkah untuk menjalankan Storyboard Studio (satu binary Go + PostgreSQL) di server Dokploy, dengan HTTPS, volume persisten, health check, dan akun admin pertama.

Semua nilai di dokumen ini diambil dari kode: Dockerfile, docker-compose.dokploy.yml, .env.example, internal/config/config.go, dan cmd/server.

Catatan tangkapan layar. Dokumen ini tidak memuat screenshot UI Dokploy karena tidak ada instance Dokploy saat dokumen dibuat. Nama menu ditulis sesuai UI Dokploy (Project → Create Service, tab Environment, Domains, Advanced). Label bisa sedikit berbeda antar versi Dokploy.

Ringkasan

Image
Build multi-stage: golang:1.26-alpine → runtime alpine:3.22 + ffmpeg, ca-certificates, tzdata. Berjalan sebagai user non-root app (UID 10001).
Port & data
Aplikasi mendengarkan 0.0.0.0:8080. File referensi dan hasil generate disimpan di /data (wajib volume).
Database
PostgreSQL 13+. Migrasi skema berjalan otomatis setiap container start. Tidak perlu langkah migrasi manual.
Buat DB→Buat aplikasi→Isi Environment→Mount /data→Domain + HTTPS→Deploy→Login admin & ganti password→Hapus ADMIN_PASSWORD

Arsitektur

Traefik milik Dokploy menerima HTTPS dan meneruskan ke container aplikasi di port 8080. Database hanya bisa dijangkau dari jaringan internal Dokploy.

Prasyarat

  • Server dengan Dokploy terpasang, dan Anda punya akses ke dashboard Dokploy.
  • Kode ada di repo Git (GitHub/GitLab/Gitea/Bitbucket) yang sudah terhubung ke Dokploy.
  • Domain (mis. storyboard.domainanda.com) punya DNS A record ke IP server Dokploy.
  • API key provider yang akan dipakai: Anthropic (wajib untuk generate nyata), BytePlus ModelArk (gambar/video), OpenAI (TTS). Tanpa key, gunakan mock untuk uji coba.
  • .env tidak di-commit. .dockerignore sudah mengecualikan .env* (kecuali .env.example), sehingga secret tidak masuk image.
API key disediakan oleh admin platform lewat Environment Dokploy dan dipakai bersama oleh semua user. Tidak ada halaman setting key di aplikasi dan bukan model BYOK. Key tidak disimpan di database dan tidak pernah ditampilkan di UI.

A1Buat database PostgreSQL

Opsi A disarankan karena backup database bisa dijadwalkan dari UI Dokploy.

  1. Buka Project → Create Service → Database → PostgreSQL.
  2. Isi Name storyboard-db, Database storyboard, User storyboard, dan generate password yang kuat.
  3. Kosongkan External Port, supaya database hanya bisa diakses dari jaringan internal Dokploy.
  4. Klik Deploy, lalu salin Internal Connection URL. Bentuknya postgresql://storyboard:…@storyboard-db-xxxx:5432/storyboard.
  5. Di tab Backups, atur tujuan S3 dan jadwal sesuai kebijakan retensi.

A2Buat aplikasi dari Dockerfile

  1. Buka Project → Create Service → Application.
  2. Provider: pilih repo Git dan branch.
  3. Build Type: Dockerfile, Dockerfile Path Dockerfile, Docker Context Path .

Nilai berikut sudah diset di Dockerfile, jadi tidak perlu diisi lagi:

Aplikasi menolak start jika: DATABASE_URL kosong; provider byteplus dipilih tanpa BYTEPLUS_API_KEY atau tanpa model ID; TTS_PROVIDER=openai tanpa OPENAI_API_KEY; PUBLIC_BASE_URL tidak memakai https://; atau TOKEN_ENC_KEY terisi tapi bukan base64 dari tepat 32 byte. Pesan errornya terlihat di tab Logs.

Daftar lengkap variabel ada di bagian Daftar environment variable.

A4Volume persisten /data

  1. Buka tab Advanced → Mounts → tambah mount.
  2. Type Volume, Volume name storyboard-media, Mount path /data.
Tanpa volume ini, semua file referensi, gambar, video, audio, dan hasil render hilang setiap redeploy. Database tetap ada, tetapi akan menunjuk ke file yang sudah tidak ada.

A5Domain & HTTPS

  1. Buka tab Domains → tambah domain.
  2. Host storyboard.domainanda.com, Container Port 8080, HTTPS on, Certificate Let's Encrypt.

HTTPS wajib: cookie sesi memakai flag Secure, jadi login tidak akan bertahan lewat HTTP biasa. Jika fitur sosial dipakai, PUBLIC_BASE_URL harus sama persis dengan domain ini (tanpa garis miring di akhir).

A6Health check

Image tidak memasang curl. Health check memanggil binary itu sendiri: /app/storyboard healthcheck melakukan GET /healthz, yang juga mengecek koneksi database.

Dockerfile sudah punya HEALTHCHECK (interval 30 dtk, timeout 5 dtk, start period 20 dtk, 3 retry). Untuk zero-downtime di mode Swarm, isi juga Advanced → Cluster Settings → Swarm Settings → Health Check:

{ "Test": ["CMD", "/app/storyboard", "healthcheck"], "Interval": 30000000000, "Timeout": 10000000000, "StartPeriod": 30000000000, "Retries": 3 }

Nilai waktu dalam nanodetik (30000000000 = 30 detik). /healthz membalas {"status":"ok"} (HTTP 200) atau {"status":"db_unavailable"} (HTTP 503). Endpoint ini tidak butuh login dan tidak membocorkan informasi lain.

A7Deploy

  1. Klik Deploy dan pantau tab Logs.
  2. Saat start, aplikasi menjalankan migrasi, lalu membuat admin pertama dari ADMIN_PASSWORD jika tabel user masih kosong.
  3. Opsional: aktifkan Auto Deploy (webhook) agar setiap push ke branch langsung di-deploy.

Lanjutkan ke Admin pertama dan Verifikasi.

BOpsi B: Docker Compose (app + Postgres satu stack)

Lebih ringkas, tetapi backup database dilakukan lewat Volume Backups, bukan backup PostgreSQL bawaan Dokploy.

  1. Buka Project → Create Service → Compose.
  2. Provider: repo Git. Compose Path: docker-compose.dokploy.yml.
  3. Tab Environment: isi minimal POSTGRES_PASSWORD, ADMIN_PASSWORD, ANTHROPIC_API_KEY, plus IMAGE_PROVIDER/VIDEO_PROVIDER dan variabel BYTEPLUS_* seperti di Opsi A. Dokploy menulisnya ke .env di samping file compose, lalu compose meneruskannya satu per satu ke container.
  4. Tab Domains: service app, port 8080, HTTPS on.
  5. Klik Deploy.
ServiceIsi
appBuild dari Dockerfile. Menunggu db sehat (depends_on: service_healthy). DATABASE_URL dirakit otomatis ke host db. Volume storyboard-media:/data.
dbpostgres:17-alpine, user/DB storyboard, port 5432 hanya expose (tidak dipublikasikan). Health check pg_isready. Volume storyboard-pg.
Di Opsi B, default provider adalah mock dan COOKIE_SECURE default true. Menghapus service dengan centang volumes akan menghapus seluruh data. Backup dulu.

Membuat secret

Linux / macOS 
# TOKEN_ENC_KEY (32 byte, base64)
openssl rand -base64 32
# Password DB / admin awal
openssl rand -base64 24
Windows PowerShell 
$b = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
[Convert]::ToBase64String($b)
Simpan cadangan TOKEN_ENC_KEY dan password DB di vault perusahaan, bukan di repo, chat, atau tiket. Isi secret hanya lewat tab Environment Dokploy.

Admin pertama & akses darurat

Admin pertama

  1. Saat deploy pertama, aplikasi membuat admin dari ADMIN_USERNAME + ADMIN_PASSWORD, hanya jika tabel user kosong.
  2. Login di https://<domain>. Aplikasi langsung meminta ganti password. Endpoint lain diblokir sampai password diganti.
  3. Hapus ADMIN_PASSWORD dari Environment, lalu redeploy.
  4. Buat akun tim di menu Admin → Pengguna. Disarankan minimal 2 admin aktif.

Jika ADMIN_PASSWORD tidak diisi dan belum ada user, log menampilkan peringatan dan tidak ada yang bisa login. Isi variabelnya lalu restart, atau pakai perintah darurat di bawah.

Akses darurat (break-glass)

Jika semua admin terkunci atau lupa password, buka Terminal container aplikasi di Dokploy:

/app/storyboard reset-password admin
  • Jika user belum ada, ia dibuat sebagai admin.
  • Jika sudah ada: password direset, kunci dibuka, akun diaktifkan, semua sesi dicabut.
  • Password sementara dicetak sekali dan wajib diganti saat login.
  • Aksi tercatat di audit log dengan pelaku cli.
Siapa pun yang punya akses Terminal Dokploy bisa membuat admin. Batasi akses dashboard Dokploy (2FA, user minimal).

Verifikasi setelah deploy

  1. Buka https://<domain>/healthz → harus {"status":"ok"}.
  2. Login sebagai admin, ganti password, hapus ADMIN_PASSWORD, redeploy.
  3. Header atas menampilkan provider aktif, mis. image: byteplus · video: byteplus. Jika masih mock, periksa Environment.
  4. Buat proyek uji dan jalankan pipeline sampai gambar dan video.
  5. Tahap Render Final: MP4 bisa diputar dan diunduh (memastikan ffmpeg di image berjalan).
  6. Redeploy sekali, lalu pastikan file proyek uji masih ada (volume /data benar).
  7. Cek log Dokploy: hanya method/path/status, tanpa token atau isi request.
  8. Jika fitur sosial dipakai: Akun Sosial → Hubungkan kembali dengan status terhubung. Uji publikasi dengan visibilitas Privat lebih dulu.

Backup, update, rollback

Backup
  • Opsi A: tab Backups pada database (S3).
  • Volume storyboard-media (dan storyboard-pg di Opsi B): fitur Volume Backups Dokploy.
  • Database dan volume saling terkait. Backup keduanya pada jadwal yang sama.
  • Uji restore secara berkala.
Update
  • Push ke branch, lalu klik Deploy (atau Auto Deploy).
  • Migrasi baru berjalan otomatis saat start.
  • Backup database sebelum update yang memuat migrasi.
Rollback
  • Deploy ulang commit sebelumnya dari tab Deployments, atau revert di Git.
  • Migrasi tidak punya skrip "down". Jika skema sudah berubah, restore backup database dari sebelum update.

Checklist keamanan produksi (ISO/IEC 27001 / UU PDP)

  • ☐ HTTPS aktif (Let's Encrypt) dan COOKIE_SECURE=true.
  • ☐ Database tanpa external port. Password DB dan API key hanya ada di Environment Dokploy.
  • ☐ Backup database + volume media terenkripsi, retensi ditetapkan, restore pernah diuji.
  • ☐ Akses dashboard dan Terminal Dokploy dibatasi (2FA, user minimal).
  • ☐ ADMIN_PASSWORD dihapus setelah admin pertama dibuat. Minimal 2 admin aktif.
  • ☐ Akun karyawan/vendor yang keluar dinonaktifkan. Daftar admin ditinjau per kuartal.
  • ☐ Rotasi API key berkala. Cadangan TOKEN_ENC_KEY ada di vault.
  • ☐ Pemisahan tugas pembuat/penyetuju post ditetapkan sebagai prosedur. Aplikasi belum mencegah admin menyetujui post buatannya sendiri.
Pemberitahuan transfer data ke pihak ketiga. Saat dipakai, aplikasi mengirim data keluar server:
  • Anthropic (Claude): brief, catatan, dan gambar referensi.
  • BytePlus (ModelArk, region ap-southeast / Singapura): prompt dan gambar referensi.
  • OpenAI: naskah voice over (TTS).
  • Google (YouTube), Meta (Instagram/Threads), TikTok: video final dan caption saat dipublikasikan.
Pastikan DPA, penilaian vendor, dan dasar hukum transfer lintas negara (UU PDP) sudah disetujui sebelum memproses data yang memuat orang atau nasabah. Jangan unggah data pribadi nasabah sebagai referensi tanpa persetujuan.
