Peran admin vs user

Aplikasi punya dua role. Setiap orang memakai akun sendiri, sehingga semua aktivitas tercatat atas nama individu di audit log.

KemampuanUserAdmin
Membuat & mengelola proyek, menjalankan semua tahap, unggah referensi, render✅✅
Menyusun publikasi (caption, jadwal) dan membatalkan post✅✅

Semua pengguna melihat semua proyek (ruang kerja bersama tim). Pembuat proyek dan post dicatat (kolom "oleh"). Pembatasan diterapkan di server: user yang memanggil endpoint admin mendapat penolakan dan tercatat sebagai forbidden di audit log.

1Membuat admin pertama

Saat database belum punya pengguna sama sekali, aplikasi membuat admin pertama dari environment variable. Pilih salah satu cara.

Cara A · Environment (disarankan)

  1. Di Dokploy → Environment, tambahkan: 
    ADMIN_USERNAME=admin
ADMIN_PASSWORD=<password awal ≥ 12 karakter>
  2. Deploy/restart. Log menampilkan first admin created.
  3. Login, ganti password (wajib), lalu hapus ADMIN_PASSWORD dari environment dan redeploy.

Cara B · Perintah di container

  1. Dokploy → aplikasi → Terminal (container berjalan).
  2. Jalankan: 
    /app/storyboard reset-password admin
  3. Salin password sementara yang tampil, lalu login. Lihat bagian 15.
ADMIN_PASSWORD hanya dipakai jika tabel pengguna kosong. Password itu harus lolos kebijakan password (lihat bagian 16), termasuk tidak memuat username. Contohnya, Admin-2026-xyz ditolak untuk username admin, dan aplikasi tidak mau start. Jika variabel ini masih diisi setelah pengguna ada, log memperingatkan agar dihapus. APP_ACCESS_TOKEN versi lama tidak dipakai lagi dan sebaiknya dihapus.

2Login & ganti password pertama

  1. Buka aplikasi, isi Username dan Password, lalu klik Masuk. Username tidak membedakan huruf besar/kecil.
  2. Akun dengan password sementara langsung diarahkan ke halaman Ganti password sementara. Fitur lain dikunci di server sampai password diganti.
  3. Isi password sementara, password baru dua kali, lalu Simpan password baru. Penghitung di bawah kolom menunjukkan panjang password.

Setelah login, header menampilkan menu Admin (khusus admin) dan nama Anda (👤 Nama · admin), yang membuka halaman Akun Saya.

4Serahkan password sementara

Jika memilih password otomatis, aplikasi menampilkan password sementara (format xxxx-xxxx-xxxx-xxxx) satu kali di atas daftar pengguna.

  • Klik Salin, lalu serahkan langsung ke pengguna lewat kanal aman (bertatap muka, atau pesan pribadi terenkripsi). Jangan lewat grup chat atau email terbuka.
  • Password tidak disimpan dalam bentuk asli (hanya hash Argon2id), jadi tidak bisa dilihat lagi. Jika hilang, lakukan Reset password.
  • Pengguna login, lalu diwajibkan mengganti password (Gambar 2).

6Ubah nama & role

  1. Ubah Nama atau pilih Role di baris pengguna.
  2. Klik Simpan. Saat role berubah, aplikasi meminta konfirmasi dan mencabut semua sesi pengguna itu, supaya hak barunya berlaku saat login berikutnya.
Pengaman bawaan: Anda tidak bisa menurunkan role akun sendiri (pilihan role di baris Anda dinonaktifkan), dan sistem menolak perubahan yang membuat tidak ada admin aktif sama sekali.

7Reset password

Untuk pengguna yang lupa password atau perangkatnya diduga disusupi.

  1. Klik Reset password di baris pengguna, lalu konfirmasi.
  2. Password lama langsung tidak berlaku, semua sesi pengguna dicabut, kunci akun dibuka, dan password sementara baru ditampilkan sekali.
  3. Serahkan password sementara seperti di bagian 4. Pengguna wajib menggantinya saat login.
Tombol ini tidak tersedia di baris akun Anda sendiri. Untuk mengganti password sendiri, gunakan Akun Saya (bagian 16).

8Buka kunci akun

Akun otomatis terkunci 15 menit setelah 5 kali berturut-turut salah password. Selama terkunci, login ditolak meskipun password benar.

  • Kunci terbuka sendiri setelah 15 menit, atau klik Buka kunci agar langsung bisa login.
  • Sebelum membuka kunci, cek audit log (filter login_failed). Jika percobaan tidak dilakukan pemiliknya, lebih aman lakukan Reset password.
  • Login sukses dan reset password juga mengembalikan penghitung gagal ke nol.

9Paksa logout

  • Tombol Paksa logout muncul jika pengguna punya sesi aktif. Gunakan saat perangkat hilang atau pengguna lupa logout di komputer bersama.
  • Di baris akun Anda sendiri, tombolnya bernama Logout perangkat lain: semua sesi dicabut kecuali sesi yang sedang Anda pakai.
  • Pengguna yang dikeluarkan bisa login lagi dengan password-nya. Jika password diduga bocor, pakai Reset password.

10Nonaktifkan / aktifkan pengguna

Pengguna tidak dihapus, hanya dinonaktifkan, agar jejak audit dan kepemilikan proyek tetap utuh.

  • Nonaktifkan: setelah konfirmasi, pengguna langsung dikeluarkan dari semua sesi dan tidak bisa login. Proyek dan data yang dibuatnya tetap ada.
  • Aktifkan: pengguna bisa login lagi dengan password lamanya. Pertimbangkan Reset password jika akun lama tidak aktif.
  • Anda tidak bisa menonaktifkan akun sendiri atau admin aktif terakhir.
Offboarding: nonaktifkan akun pada hari terakhir karyawan atau vendor bekerja (ISO/IEC 27001 A.5.18, A.6.5).

  2. Aksi: pilih jenis aksi, lalu klik Terapkan filter.

12Akun sosial media perusahaan

Hanya admin yang bisa menghubungkan dan memutus akun YouTube, Instagram, Threads, dan TikTok. User hanya melihat daftar akun dan memakainya saat publikasi.

  1. Klik Akun Sosial, lalu Hubungkan pada platform.
  2. Login dengan akun resmi perusahaan di halaman platform dan beri izin.
  3. Token disimpan terenkripsi (AES-256-GCM) dan diperbarui otomatis. Tanggal "token s/d" menunjukkan masa berlaku.
  4. Putuskan menghapus token, dan post yang belum terkirim ke akun itu otomatis dibatalkan.
Tombol Hubungkan nonaktif dengan teks "Belum dikonfigurasi admin" jika client id/secret platform atau TOKEN_ENC_KEY belum diisi. Jika PUBLIC_BASE_URL kosong, halaman menampilkan peringatan karena login platform (OAuth) dan pengambilan video Instagram/Threads tidak akan berfungsi. Lihat bagian 14.

13Persetujuan publikasi

Dengan POST_APPROVAL=true (default), post buatan user berstatus Menunggu persetujuan. Scheduler hanya mengirim post yang sudah disetujui admin.

  1. Buka proyek → tahap Render Final → kartu 📣 Publikasi → Riwayat & antrean.
  2. Periksa video final, caption, akun tujuan, jadwal, dan label AI.
  3. Klik Setujui. Status menjadi Terjadwal dan post dikirim pada waktunya. Klik Batal untuk menolak.
Aplikasi saat ini tidak mencegah admin menyetujui post buatannya sendiri. Jika kebijakan perusahaan mewajibkan prinsip 4 mata (maker-checker), tetapkan sebagai prosedur: post buatan admin disetujui admin lain. Kepatuhannya bisa dicek di kolom "Oleh" dan di audit log.

14API key provider (Claude, BytePlus, OpenAI, sosial media)

API key disediakan oleh admin platform dan dipakai bersama oleh semua pengguna. Pengguna tidak memasukkan key sendiri (bukan BYOK). Tidak ada halaman settings di aplikasi: key hanya diatur lewat environment variable server (Dokploy → Environment), tidak disimpan di database, dan tidak pernah ditampilkan di UI.

15Akses darurat: perintah reset-password

Dipakai jika semua admin terkunci, lupa password, atau admin pertama belum ada.

/app/storyboard reset-password <username>
  • Jalankan di Terminal container (Dokploy). Perintah memakai environment yang sama dengan aplikasi.
  • Jika username belum ada: dibuat sebagai admin baru.
  • Jika sudah ada: password diganti, kunci dibuka, akun diaktifkan kembali, dan semua sesi dicabut. Role tidak berubah.
  • Password sementara dicetak sekali di terminal. Pengguna wajib menggantinya saat login.
  • Tercatat di audit log dengan pelaku cli. Batasi akses terminal Dokploy hanya untuk admin infrastruktur.
Password "admin" direset, akun dibuka & diaktifkan, semua sesi dicabut.
Password sementara (wajib diganti saat login): xxxx-xxxx-xxxx-xxxx

16Kebijakan keamanan bawaan

Password

  • 12–128 karakter. Disarankan kalimat sandi (mis. 4 kata acak).
  • Tidak boleh memuat username, tidak boleh password umum, minimal 5 karakter berbeda.
  • Disimpan sebagai hash Argon2id, tidak pernah dalam bentuk asli.
  • Mengganti password mengeluarkan sesi di perangkat lain.

Login & sesi

  • Penguncian akun: 5× salah berturut-turut → terkunci 15 menit.
  • Batas per IP: 10 percobaan gagal per 15 menit → "terlalu banyak percobaan login". Penghitung ini direset saat aplikasi restart.
  • Pesan gagal sengaja umum, tidak memberi tahu apakah username terdaftar.
  • Sesi berakhir setelah SESSION_TTL_HOURS (default 12 jam) atau SESSION_IDLE_MINUTES tanpa aktivitas (default 60 menit).
  • Cookie HttpOnly, SameSite=Strict, Secure saat HTTPS.
