Lisensi Storyboard Studio

Storyboard Studio adalah software open source dengan dual licensing: gratis di bawah GNU AGPL-3.0, atau berbayar di bawah lisensi komersial. Halaman ini menjelaskan artinya untuk pengguna, perusahaan, kontributor, dan pemilik proyek.

Panduan ini penjelasan umum, bukan nasihat hukum. Yang mengikat adalah teks di LICENSE (AGPL-3.0) dan perjanjian lisensi komersial yang ditandatangani. Untuk kasus spesifik, konsultasikan dengan konsultan HKI.

1Apa itu dual licensing

Pemegang hak cipta merilis kode yang sama di bawah dua lisensi. Pengguna memilih salah satu, tidak perlu keduanya.

Model ini hanya bisa dijalankan jika pemegang hak cipta memiliki (atau berhak melisensikan ulang) seluruh kode. Karena itu kontributor luar wajib menandatangani CLA.

2AGPL-3.0 dengan bahasa sederhana

✅ Boleh
  • Memakai untuk tujuan apa pun, termasuk komersial.
  • Menjalankan di server sendiri dan memungut biaya layanan.
  • Mempelajari dan mengubah kode.
  • Mendistribusikan salinan asli atau versi modifikasi.
📋 Wajib
  • Menyertakan teks lisensi dan pemberitahuan hak cipta.
  • Versi modifikasi yang didistribusikan dirilis di bawah AGPL-3.0, beserta source code-nya.
  • Pasal 13: jika versi modifikasi dipakai pengguna lewat jaringan (web), pengguna tersebut harus ditawari source code versi itu.
  • Menandai bahwa file telah diubah, beserta tanggalnya.
Pasal 13 adalah pembeda AGPL dari GPL. Dengan GPL, perusahaan bisa memodifikasi lalu menjual layanan web tanpa membuka kode, karena tidak ada "distribusi". AGPL menutup celah itu, sehingga perusahaan yang ingin tertutup punya alasan membeli lisensi komersial.

Versi yang dipakai adalah AGPL-3.0-only, bukan "or later". Jadi versi AGPL baru di masa depan tidak otomatis berlaku tanpa keputusan pemegang hak cipta.

4Lisensi komersial

Lisensi berbayar yang membebaskan pembeli dari kewajiban AGPL. Rincian ada di COMMERCIAL-LICENSE.md.

Internal
Modifikasi tertutup untuk kebutuhan perusahaan sendiri.
OEM / white-label
Digabung ke produk pembeli, dengan merek pembeli.
SaaS / reseller
Menjual layanan hosted ke pelanggan tanpa membuka kode.
  • Berlaku hanya setelah perjanjian tertulis ditandatangani. COMMERCIAL-LICENSE.md hanya penjelasan.
  • Tidak mencakup komponen pihak ketiga (tetap lisensi masing-masing) maupun layanan API (Anthropic, BytePlus, OpenAI, Google, Meta, TikTok).
  • Bisa ditambah support, SLA, instalasi, dan kustomisasi sebagai sumber revenue tambahan.

5Kontributor & CLA

CLA (Contributor License Agreement) membuat kontribusi luar bisa ikut dijual di lisensi komersial.

  1. Kontributor tetap memegang hak cipta atas kontribusinya.
  2. Kontributor memberi pemegang hak cipta proyek lisensi luas, termasuk hak melisensikan ulang secara komersial, plus lisensi paten.
  3. Sebagai imbalan, pemegang hak cipta berjanji setiap kontribusi yang dirilis juga tersedia di bawah AGPL-3.0 (atau lisensi OSI lain).
  4. Cara tanda tangan: komentar di pull request pertama:
    I have read the CLA Document and I hereby sign the CLA.
  5. Kontribusi atas nama perusahaan memerlukan CLA korporat.
Tanpa CLA, kontribusi orang lain hanya berlisensi AGPL. Kontribusi itu tidak boleh ikut dijual di lisensi komersial, sehingga model dual licensing rusak. Jangan merge pull request sebelum CLA ditandatangani. Bot seperti CLA Assistant bisa mengotomatiskan pengecekan ini.

Aturan dependency untuk kontributor (CONTRIBUTING.md): hanya lisensi permissive (MIT, BSD, Apache-2.0, ISC). Kode GPL/AGPL milik pihak lain tidak bisa diterima, karena tidak bisa dilisensikan ulang secara komersial.

FFmpeg di image Docker

Aplikasi memanggil ffmpeg sebagai program terpisah dan tidak me-link-nya, jadi kode Storyboard Studio tidak terkena lisensi FFmpeg. Tetapi image Docker berisi FFmpeg dari paket Alpine (LGPL-2.1+ atau GPL-2.0+, tergantung opsi build). Jika image didistribusikan, sertakan lisensinya dan tawarkan source-nya. Cek lisensi persisnya dengan:

docker run --rm --entrypoint apk <image> info --license ffmpeg

Deploy di server sendiri (mis. Dokploy) tanpa membagikan image ke pihak lain bukan distribusi.

7Merek dagang

Lisensi hak cipta tidak memberi hak atas nama dan logo. Siapa pun boleh fork kodenya, tetapi tidak boleh memakai nama "Storyboard Studio" untuk produknya, kecuali untuk menyebut asal software (mis. "berbasis Storyboard Studio").

Agar perlindungan ini kuat secara hukum, daftarkan merek (di Indonesia lewat DJKI).

9Tugas pemilik proyek sebelum rilis publik

  • ☐ Pastikan kepemilikan hak cipta. Jika dibuat sebagai karyawan, di jam kerja, atau dengan perangkat/akun kantor, hak cipta bisa milik perusahaan sesuai kontrak kerja. Minta izin atau pengalihan tertulis.
  • ☐ Isi placeholder [NAMA PEMEGANG HAK CIPTA], [EMAIL LISENSI], dan [EMAIL KEAMANAN] di NOTICE, COMMERCIAL-LICENSE.md, CLA.md, CONTRIBUTING.md. Gunakan email khusus (mis. licensing@…), bukan email pribadi.
  • ☐ Minta konsultan HKI meninjau CLA.md (termasuk hukum yang berlaku) dan menyusun template perjanjian lisensi komersial.
  • ☐ Pasang bot CLA di repo dan simpan catatan tanda tangan.
  • ☐ Daftarkan merek "Storyboard Studio".
  • ☐ Bersihkan repo dan riwayat Git dari secret, .env, data/screenshot nasabah, serta nama atau domain internal (ISO/IEC 27001 A.5.14, A.8.12). Screenshot tutorial saat ini hanya berisi data fiktif.
  • ☐ Saran: tambahkan link "Source code" di UI aplikasi, agar fork yang memodifikasi lebih mudah memenuhi pasal 13.

FAQ

Apakah video yang dibuat dengan Storyboard Studio ikut berlisensi AGPL?

Tidak. Menurut AGPL pasal 2, output program hanya tercakup lisensi jika isinya sendiri merupakan karya yang dilindungi lisensi (mis. memuat kode program). Storyboard, naskah, gambar, dan video milik pengguna, tunduk pada ketentuan provider AI yang dipakai.

Bolehkah saya menarik biaya untuk layanan berbasis AGPL?

Boleh. AGPL tidak melarang menjual layanan atau salinan. Kewajibannya adalah membuka source code versi modifikasi kepada pengguna atau penerima.

Bisakah lisensinya diganti di kemudian hari?

Pemegang hak cipta bisa merilis versi baru dengan lisensi lain, karena CLA memberi hak melisensikan ulang kontribusi. Rilis lama yang sudah keluar di bawah AGPL tetap AGPL bagi yang sudah menerimanya.

Apakah memanggil API Claude, BytePlus, atau OpenAI membuat mereka terikat AGPL?

Tidak. Itu layanan eksternal yang diatur oleh syarat layanan masing-masing. Operator butuh akun, perjanjian, dan DPA sendiri jika memproses data pribadi.

Kalau saya hanya mengganti logo dan warna lalu menjualnya sebagai produk sendiri?

Itu modifikasi. Di bawah AGPL Anda wajib membuka kodenya dan tidak boleh memakai nama "Storyboard Studio". Untuk white-label tertutup, butuh lisensi komersial.
